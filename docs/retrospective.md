# PEVO.US Project Retrospective

## What Went Well

One of the things that went well during this project was that I had a clear idea of what I wanted the website to include. I already had the project scope, so I knew that the website needed two pages, one CSS file, project documentation, and a live version through GitHub Pages.

I also became more comfortable using GitHub, Markdown, HTML, and CSS during this project. At the beginning of the course, some of these tools were new to me, but working through the assignments helped me understand how they work together. Organizing the project into smaller files and sections also made the work easier to manage.

## What Went Wrong

The biggest challenge for me was time management. I sometimes waited too long before starting parts of the project, which made small problems feel more stressful than they really were.

I also had to spend extra time checking formatting, file names, links, and the structure of the repository. Small mistakes in HTML, CSS, Markdown, or GitHub can affect how the final project works, so I learned that I need to review these details carefully.

## What I Would Do Differently

If I were starting this project again, I would begin earlier and divide the work into smaller steps from the beginning. I would create the repository structure first, then complete the documentation, website pages, CSS, testing, and final review in order.

I would also test the website after every major change instead of waiting until the end. This would make it easier to find problems early and reduce the amount of work needed before submission.

Overall, this project helped me understand that planning, organization, testing, and reviewing the work are just as important as writing the code itself.
